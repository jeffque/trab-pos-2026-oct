# ADR-008: Isolamento dos workers que compilam código de usuário

## Status
Accepted (2026-10-30)

## Contexto
Os workers rodam o gcc (compilação de workspaces) e o linker (assemblagens) sobre código enviado por qualquer usuário. Mesmo sem executar o programa, compilar envolve riscos: `#include "/etc/passwd"` vaza arquivos para o log de erro, código pode explodir o tempo ou a memória do compilador, e um nome de arquivo como `-fplugin=...` seria lido como opção do gcc.

## Alternativas consideradas
1. **Compilar no mesmo container do source-service**: o código não confiável dividiria processo, rede e credenciais com o serviço de negócio.
2. **Sandbox forte** (gVisor, nsjail, Firecracker): o melhor isolamento, mas complexo para o prazo.
3. **Container dedicado com limites de recursos e defesas no processo**.

## Decisão
O build roda em containers próprios (`compila-worker`, `assembla-worker`), separados dos serviços de negócio, com:
- o programa linkado **nunca é executado** no servidor (o usuário baixa o executável, ligado estaticamente);
- `gcc` e `ld` via `execFile` (sem shell), timeout de 10 s com SIGKILL, saída limitada a 1 MB, **sem herdar variáveis de ambiente** (só `PATH`);
- diretório temporário por build, apagado ao final; `/tmp` em tmpfs;
- limites no compose: `mem_limit: 512m`, `cpus: 1.0`, `pids_limit: 128`;
- nome do arquivo sanitizado: só o basename, caracteres seguros, sem `-` inicial.

## Consequências

Positivas:
- Um build abusivo afeta só aquele worker (limite de CPU, memória e processos); o resto do sistema continua.
- O container do worker não tem banco nem credenciais; ele só fala com os LBs e com o RabbitMQ.

Negativas / Trade-offs:
- `-static` gera executáveis maiores (~137 kB para um programa pequeno).
- Isolamento de container não é uma sandbox de segurança completa.

Riscos:
- O worker ainda tem acesso à rede interna do compose. Mitigação: rede dedicada só com `source-lb` e `blob-lb`, ou sandbox (gVisor) como próximo passo.
- `#include` de arquivos do próprio container ainda aparece no log. Mitigação parcial: o container do worker não guarda segredos; próximo passo é `-nostdinc` + lista de includes permitidos.
