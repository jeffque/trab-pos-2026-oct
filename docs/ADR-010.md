# ADR-010: Conteúdo em BYTEA no Postgres e versões como array JSONB

## Status
Accepted (2026-10-30)

## Contexto
Precisamos guardar o conteúdo de cada revisão e artefato (blob-service) e a lista de revisões de cada arquivo (source-service). Arquivos são pequenos (código C; limite de 10 MB por blob) e o volume estimado é baixo (ver arquitetura.md, seção 1).

## Alternativas consideradas
Para o conteúdo:
1. **Object storage (MinIO/S3)**: o padrão de mercado para bytes; mais um componente para operar.
2. **Sistema de arquivos com volume**: simples, mas não escala com réplicas sem storage compartilhado.
3. **`BYTEA` no Postgres do blob-service**, com `md5` gerado pelo banco.

Para as versões:
1. **Tabela `version (source_id, version, blob_id)`**: normalizada, mas exige JOIN e controle de concorrência para numerar.
2. **Array JSONB `versions` na própria linha de `source`**: a lista inteira vem numa leitura, e o número da nova versão é calculado atomicamente no UPDATE.

## Decisão
O conteúdo fica em `BYTEA` na tabela `blob.storage`, atrás do contrato HTTP do blob-service. As versões ficam em `versions JSONB` (`[{version, blob_id}]`), com o número da nova versão calculado dentro do UPDATE (`jsonb_array_length(versions) + 1`), que fica protegido pela trava de linha do Postgres.

## Consequências

Positivas:
- Um único tipo de banco para operar; backup e transações iguais em todo o projeto.
- Revisões numeradas sem condição de corrida e lidas numa só consulta.
- Como o blob é acessado só pela API, trocar `BYTEA` por MinIO/S3 depois não muda nenhum outro serviço.

Negativas / Trade-offs:
- `BYTEA` não serve para arquivos grandes: o conteúdo inteiro passa pela memória do serviço, e hoje o JSON do `GET /blob/:id` serializa os bytes como array de números.
- O array JSONB cresce sem limite numa única linha; arquivos com milhares de revisões ficam pesados.

Riscos:
- Crescimento do banco do blob. Mitigação: migrar o conteúdo para object storage quando passar de alguns GB (o contrato HTTP já permite) e coletar blobs órfãos (ADR-001).
