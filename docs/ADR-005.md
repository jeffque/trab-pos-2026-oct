# ADR-005: Um Postgres com schema por serviço

## Status
Accepted em 2026-10-22; Superseded by [ADR-006](ADR-006.md) em 2026-10-30

## Contexto
No início do projeto, cada serviço precisava de dados próprios, mas operar vários bancos parecia custo demais para o ambiente local. A Aula 3 descreve a decomposição do banco em fases: (1) banco compartilhado, (2) schemas separados no mesmo servidor, (3) bancos separados.

## Alternativas consideradas
1. **Banco e schema compartilhados**: zero isolamento.
2. **Um Postgres com um schema por serviço** (Fase 2).
3. **Um Postgres por serviço** (Fase 3).

## Decisão
Usaríamos um único container Postgres com os schemas `blob` e `source`, criados pelo `postgres-schemas/creator.sh`.

## Consequências

Positivas:
- Um só container para operar.

Negativas / Trade-offs:
- O isolamento é só lógico: os dois serviços usam o mesmo usuário e o mesmo servidor, e um pico de um afeta o outro.

Riscos (que se confirmaram):
- **As tabelas estavam sendo criadas no schema `public`**: os scripts não usavam o nome do schema e os serviços não configuravam o `search_path`. Na prática não havia separação nenhuma. O problema foi encontrado ao implementar a tabela de builds e corrigido, e a decisão foi revista no ADR-006.
